# 手工测试清单

自动化测试（`test.bat`）用 mock 替代了模型和外部接口。下面这些需要真实 Key 和真实返回，只能手工检查。每次改动外部适配器或提示词后，挑相关的几项跑一遍。

日期请选未来 1～2 个月内、确实有车次和库存的日期。

## 服务生命周期

- [ ] 双击 `start.bat`，自动打开 http://127.0.0.1:8000；再次双击只打开网页，不启动第二个服务。
- [ ] 8000 端口被其他程序占用时，给出明确提示，不结束其他进程。
- [ ] `stop.bat` 后接口不再响应；重新启动后旅行数据、模型配置、攻略选择都在。
- [ ] 规划进行中执行 `stop.bat`，再 `start.bat`：任务显示为「可恢复」，点击「继续本次任务」从检查点继续。

## 主流程

示例：北京出发，杭州 → 苏州，3 天，2 人 1 间双床房，预算 5000，「少走路」。

- [ ] 导入或搜索 2～3 篇攻略，勾选后生成候选。
- [ ] 每个景点和餐厅都能点开看到原文片段或图片序号。
- [ ] 日期严格覆盖起止日，城市顺序是杭州 → 苏州。
- [ ] 每段移动显示方式、耗时、是否为高德实际查询（而不是估算）。
- [ ] 审查面板显示 10 个检查维度的结论；有阻断时「确认」按钮不可用。
- [ ] 确认后生成每日行程；点「保存行程」才产生新版本号。

## 去重

- [ ] 两篇攻略用不同名字写同一个景点（如「西湖」和「西湖风景区」）：全程只安排一次，两个来源都保留。
- [ ] 同品牌不同分店：不被误合并，显示具体分店地址。
- [ ] 同一家餐厅在午餐、晚餐、不同日期都只推荐一次。

## 中断与取舍

- [ ] 把一个大景点设为必去，并把天数压到排不下：系统只问一道具体的取舍问题，不要求用户「批准修复」。
- [ ] 回答后从原位置继续，不重新解析攻略。
- [ ] 在等待回答时修改需求表：旧问题失效，提示重新开始。
- [ ] 在两个浏览器标签页同时提交：后提交的一方收到 409「已更新，请刷新」。

## 局部修改与资源切换

- [ ] 在候选上只改第二天：其他日期内容不变，审查重新执行。
- [ ] 切换为另一个车次或酒店：只重算受影响的城市和日期，「本次变化」列出差异。
- [ ] 报价超过 10 分钟后确认：提示先「更新报价与路线」。

## 外部失败

- [ ] 未配置高德：路线标为估算，候选无法通过审查，界面说明原因。
- [ ] 未配置飞猪：交通、酒店、门票显示未知，不出现编造的价格。
- [ ] 模型返回格式错误或超时：保留上一轮草稿，显示失败原因，可「继续本次任务」。
- [ ] 关闭图文模型后导入纯图片攻略：明确报错，不出现凭空写出的景点。

## 地图导出

- [ ] 「导出到手机高德」生成二维码和链接，导出不会让已通过的审查失效。
- [ ] 行程重排后，旧导出链接被清除。
