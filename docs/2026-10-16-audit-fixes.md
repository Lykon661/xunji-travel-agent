# 2026-10-16 静态审查修复

状态：源码已修改，回归用例已补充；未运行测试、构建、服务、模型或平台查询，也未进行浏览器验证。验收由用户执行，前端生产包未重建。

## 修复内容

1. 开放时间：区分明确闭馆与解析未知；地图日历无法确定时，不再采用攻略的普通时段覆盖。攻略也使用日期、星期与多个开放窗口解析。普通活动在闭馆日不安排；锁定活动保留问题并阻止确认，避免静默删除。
2. 步行指令：将预算、价格、车程等条件与步行条件分开处理。“保持规划，预算不要超过5000元”不再恢复步行上限，也不因“全程预算”扩大豁免日期。
3. 接驳汇总：按实际到离日期归集城际出发/到达接驳，补入每日步行与市内交通参考费用。已在当天路线中出现的车站接驳不重复计入；没有具体出发地址时不新增虚构路段。补入的接驳在每日行程中单独显示。
4. 地图导出：统一使用排除 `personal_map` 的行程指纹。导出链接和导出时间不使有效审查失效；活动、费用、需求、锁定及查询依据的变更仍按原门禁重新审查。重排后的旧导出链接会清除。
5. 停止任务：取消规划任务时向模型工作线程传递取消信号，结束本次调用的 Node 子进程，等待清理后返回；不按进程名批量结束其他程序。

## 优化内容

- 历史版本新增轻量目录查询与单版本正文查询。旧完整列表接口仍兼容；前端仅在进入旅行、版本变化、回退或删除历史等时刷新目录，选择某版后才读取该版正文，并缓存已读正文。运行状态轮询不再下载所有历史，也不再重复下载整个旅行列表。
- 飞猪与高德内存缓存分别设置最多512项；访问/写入时淘汰过期数据。飞猪缓存10分钟，地图路线5分钟、天气15分钟，其他地图缓存最多30分钟。删除旅行或回退流程时清理对应缓存；旅行互斥锁使用弱引用，闲置后释放。

审查策略版本已更新。旧候选的旧审查报告不能直接用于新版本确认，需重新审查；已保存的历史版本不被改写。

## 留给用户的验收

在项目根目录依次运行 `stop.bat`、`build.bat`、`start.bat`，然后在网页按 `Ctrl+F5`。

建议重点查看：

- 对步行超限问题回答“保持这个规划，预算不要超过5000元”，确认只豁免受影响日期；再回答“步行不要超过8000米”，确认恢复限制。
- 使用有周一闭馆、多时段或节假日例外的攻略，确认闭馆与未知状态没有变成普通营业窗口。
- 为出发地填写具体地址，确认出发/返程接驳计入每日步行和参考费用；当天已有的站点接驳不重复。
- 导出已确认路线到手机高德，确认审查状态未因导出失效。
- 在模型调用中停止服务，再重新启动，确认没有等待原模型超时或残留项目实例阻止启动。
- 保存多版行程后切换查看、删除历史版本、返回上一步，确认各版本内容、来源及列表对应正确。
