# 循迹：基于小红书攻略的多 Agent 旅行规划

本机单用户网页版。用户选择参考攻略后，攻略 Agent 整理有来源的地点，资源 Agent 查询交通、住宿和门票，行程 Agent 安排路线、时段与全程餐饮推荐，检验 Agent 对完整候选独立重审。必要取舍原地问一道问题；确定重复、关键依据缺失或重审失败时保留待处理草稿。支持局部修改、备选资源切换、独立酒店与门票查询、高德地图交付、锁定、历史版本、SSE 进度和任务恢复。

**本次四 Agent、全程去重与独立重审改造只更新源码，未生成新的前端生产包，未运行测试、构建、服务、模型调用、外部接口或浏览器检查。** 前后端合并为一个本机后台服务；外部接入由你验收，页面中的“已配置”只检查配置是否存在。启动新版前请由你运行 `stop.bat`、`build.bat`、`start.bat`，再按 `Ctrl+F5` 刷新页面。

2026-10-16 的静态审查修复覆盖开放时间、步行指令、城际接驳统计、地图导出与模型取消，并优化历史版本加载和缓存清理。源码及回归用例已更新，尚未运行验收；说明见 [审查修复记录](docs/2026-10-16-audit-fixes.md)。

## 联合规划与酒店、门票查询

规划顺序为：所选攻略与已确认需求 → 内部草案 → 资源与地图查证 → 完整每日行程与独立检验 → 候选确认 → 手动保存。候选卡展示交通时刻、住宿推荐区域、可用时段、已知费用与估算、仍有的冲突。酒店只有用户明确采用后才计入日程和费用，未选择不暂用，也不阻止规划。确认须使用十分钟内且依据、约束未变化的审查报告；过期后需重新审查。查证不代表库存或最终价格保证。

- 需求新增儿童人数/年龄、具体出发地址、最早出发/最晚到达/最晚返程、城际最长耗时、直达、舱位/坐席、住宿类型/星级、每日步行上限与允许打车。日期仍严格遵守用户输入，不自动浮动。跨时区航程的当地时刻、行李、税费与中转衔接仍需核对供应商页面。
- 飞猪交通分别查询推荐、价格和耗时排序，再检查明确时间条件，保留完整分段及舱位。高德比较车站/机场两端接驳；未提供出发地址或部分路线未知时，不填确定的完整门到门耗时。
- 酒店围绕候选实际采用的活动选择最多三个查询区域，最多六个酒店进入通勤比较，结合景点和车站/机场接驳选址。价格上限扣除已知城际费用与餐饮估算后分配；未知门票和儿童费用会继续展示，不能保证满足总预算。
- 飞猪酒店查询的床型条件不证明具体房型、房间容量或多人多房库存。酒店列表展示价只作明确标注的参考估算；多晚价格及取消/含早条件缺失时保留未知。成人价不能套用于儿童；存在儿童时成人部分单独估算，整段费用不计为已知总价。
- 交通、住宿卡提供“采用并重算”，只接受当前已查询的备选 ID，检查版本、更新时间、锁定和硬性条件。超过十分钟的报价要求先“更新报价与路线”。切换会重算相关城市/日期，用户本次手动选择的资源不会被自动修复替换。刷新后的班次、展示价、天气及日程变化在“本次变化”中说明。
- 一日游从到达站直接开始游玩，再前往返程站；用户已采用酒店时才计算放行李和住宿接驳。未选酒店时行程不设酒店起终点，费用不含住宿。餐饮推荐只采用用户所选攻略中的餐饮地点，并扫描全程重复；不保证营业、餐位或消费。每日步行统计不含景区内部游览，超过上限会保留冲突。
- 每个规划任务复用一次高德 MCP 会话与工具清单，按实际输入 schema 调用；地图调用串行且最多300次，达到上限或连接失败时保留待确认项。飞猪成功结果缓存十分钟，路线缓存五分钟，天气缓存十五分钟；点击更新报价绕过飞猪缓存。正常无库存或权限错误不反复以相同条件重查。
- 冲突修复最多两轮，先比较能增加可用时间的班次或减少步行的酒店，再重排相关日程，最后减少未锁定活动；硬冲突不能解决时交给用户调整。

“酒店与门票”只提供酒店查询与景点门票参考查询。酒店可按城市、入住退房日期、区域、床型、星级和价格区间筛选；门票按城市和景点名称查询参考资料。搜索结果最多保留48项，不自动新增景点或预订。通用商品、完整需求和套餐搜索入口及其接口模式已移除。

“收藏为参考”只保存酒店或门票查询结果，不改变每日行程。独立查询不再提供体验商品加入行程的操作；采用行程住宿仍使用住宿卡的明确选择流程。历史记录保留。门票接口不保证指定日期库存，具体票种、房型与最终费用需在预订页核对；当前不支持自动出票、下单或支付。

点击“生成高德专属地图”只导入已定位地点，未定位点会单列；工具或 schema 未开放时展示真实错误，不生成替代链接。逐项导航使用高德官方 URI，兼容桌面查看和移动端唤起。明确允许打车后可生成相应路段的高德打车入口，仍由用户在高德确认叫车与费用。天气只采用返回且日期匹配的预报，高德基础预报通常为当天及未来三天；远期日期保留天气未知。

新接口：`POST /api/trips/{id}/resources/select`、`products/search`、`products/select`、`maps`、`taxi`。资源采用、查询结果收藏和地图操作带 `base_version` 与 `updated_at`；`products/search` 仅接受 `hotel`、`poi` 模式，使用 `base_version`，不要求模型。`products/select` 仅收藏参考，不接受日期、地点或体验时长。

## 1. 安装与启动（Windows）

准备 Python 3.11 或更高版本（推荐 3.11）和 Node.js 22.19 或更高版本，然后双击项目根目录的 **`start.bat`**。前端打包为 `frontend/dist/` 静态文件，由 FastAPI 与 API 一起提供，只启动一个后台 Python 服务，不再启动 Vite 开发服务器。脚本在缺少依赖时调用现有安装脚本，保留已有的 `backend/.env`；前端尚未打包或源码比生产包更新时会自动重新打包。首次安装需要联网；可选采集器仍按第 2 节安装，需要 Git。

如果提示没有可用的 Python，且使用的是 Python Install Manager，可先运行 `py install 3.11`，再双击 `start.bat`。其他安装方式请安装 Python 3.11 并启用启动器或加入 PATH。

服务就绪后会自动打开 **http://127.0.0.1:8000**，启动窗口随后关闭。关闭网页、关闭启动窗口不影响已启动的后台服务；重复双击只重新打开网页。首次从旧启动方式切换时，先关闭原来的前后端终端，否则旧后端会占用 `8000` 端口。

- **`stop.bat`**：通知后台服务正常退出，等待当前请求结束并执行任务清理。只针对本项目的启动实例，不按名称批量结束 Python 或 Node 进程。
- **`build.bat`**：重新生成前端生产包。先停止服务，打包后再启动；后端直接使用项目虚拟环境和现有模型运行依赖，与前端合并部署。这是本机运行方式，仍需要 Python 和 Node.js 环境，未制作为独立 EXE 安装包。
- **`backend/data/server.log`**：后台运行日志；启动失败时根据窗口提示查看这个文件。

模型在页面右上角“模型配置”接入；外部服务仍编辑 `backend/.env`，修改环境配置或后端代码后双击 `stop.bat`，再双击 `start.bat`。不会随 Windows 开机自动启动；重启电脑后重新双击 `start.bat`。后台启动和停止流程尚未运行验证。

如需手动安装，在本项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

这个脚本安装前后端及模型运行依赖，并在不存在时复制 `backend/.env.example` 为 `backend/.env`，不执行测试或构建。执行策略只作用于这个 PowerShell 进程，不更改系统策略。也可手动安装：

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

另一个终端进入 `frontend` 执行 `npm install`。已有 `.env` 时不要重复复制。

模型可在页面右上角配置。日常使用 `start.bat` / `stop.bat`。需要调试源码时，原有双终端开发入口仍保留，在项目根目录分别执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1
```

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-frontend.ps1
```

开发模式打开 **http://127.0.0.1:5173**，合并后台模式打开 **http://127.0.0.1:8000**；不要同时启动两个后端。接口文档在 http://127.0.0.1:8000/docs 。后端绑定回环地址，拒绝其他 Host 和跨站写入；当前无账号系统，不要直接开放到公网。

### 模型配置

页面右上角点击 **模型配置**。接入方式沿用期末复习 Agent：服务商连接与多个模型分开管理，通过 pi-ai 调用，支持内置目录、自定义兼容接口、API Key、环境变量、本地免密钥服务和订阅 OAuth 登录。

1. 添加服务商，填写接口根地址和凭据，或选择“模型订阅登录”并按授权提示登录。
2. 从内置目录添加模型，也可获取兼容服务的 `/models` 列表或手动填写模型 ID。
3. 只有一个可用模型时，保存后会自动选择；有多个模型时点击“选择用于旅行规划”，再保存。文本需求理解、路线比较和行程细化使用当前模型。已有唯一模型配置但未选择的旧数据会在启动时自动补齐选择。
4. 图片攻略可另选支持图片的模型，点击“选择用于攻略图片”；不另选时跟随旅行规划模型，但它必须支持图片。

保存后直接生效，旅行任务运行期间禁止保存或切换。可独立删除服务商、移除模型或退出订阅。API Key 与订阅凭据保存在 `backend/data/model-config.json`、`backend/data/model-auth/`，读取配置的接口不会返回密钥或 token。**不要将这些数据文件公开或提交到 Git。** “检查所选模型”由用户点击后发送一条文字请求，可能产生少量费用，并不测试图片能力。

模型运行依赖位于 `model-runtime/`，要求 **Node.js 22.19+**，固定使用 `@earendil-works/pi-ai` 1.0.4。`start.bat` 会在缺少依赖时调用安装脚本；手动启动的用户先执行 `scripts/setup.ps1`，或单独执行：

```powershell
npm.cmd ci --prefix model-runtime
```

原有 `TEXT_BASE_URL / TEXT_MODEL / TEXT_API_KEY` 与 `VISION_*` 仍兼容：没有已保存配置时，从 `backend/.env` 导入为两个连接；保存网页配置后优先使用保存值。采集器启用状态优先使用前端管理保存的 `backend/data/crawler-config.json`，即时生效；高德 Key 和飞猪 API Key 可分别在右上角“高德配置”“飞猪配置”保存，即时生效。采集路径、飞猪 CLI 路径与启用开关等环境设置仍在 `.env`，修改环境配置需重启后端。接入状态只显示统一的“模型”状态与当前名称，不拆分文字和图文。

模型只返回经过 Pydantic 校验的 JSON。格式异常、截断或图片能力不匹配会展示错误，不采用无法校验的输出。

### 旅行攻略搜索入口

左侧 **搜索旅行攻略**、首页同名按钮，或旅行内的 **参考攻略** 页均可进入搜索。

- 填写目的地城市和可选关键词，如“杭州 / 三天两晚 少走路”，点击 **搜索攻略**。
- 城市和关键词至少填一个，不需要先填写日期、人数、房间数、预算，也不需要模型。
- 没有打开旅行时，入口会创建“旅行攻略收藏”；结果保存在当前旅行中，可直接查看正文、图片和原帖。
- 搜索调用现有 MediaCrawler 适配器。在页面右上角“小红书采集器”完成安装、登录和启动即可；未启动或登录失效会显示真实错误，也可手动导入。
- 收集好攻略后，勾选一篇或多篇想参考的攻略（最多二十篇），填写完整旅行需求，点击 **根据所选攻略生成候选路线**。只解析所选攻略，不自动挑选其他资料；选择随规划任务及历史版本保存。具体流程见下方“协作规划与路线确认”。
- 候选路线由模型组合所选攻略的活动，起止日期均计入旅行天数。比如 11 月 10–12 日必须恰好三天，即使参考攻略原有五天，也只能删减或合并为三天，并说明调整。
- 后端严格校验日期列表、城市顺序和活动来源。全部候选不合格时纠正一次，仍不合格则不展示；确认完整候选时再次校验。修改旅行需求或勾选攻略后，须重新生成候选，旧路线不能继续采用。

## 2. 小红书采集

采集器是可选的独立环境；未安装或账号异常时可先导入攻略正文和图片使用规划流程。链接用于保留来源，规划时不再自动抓取链接正文。

需要自动采集时执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -WithCrawler
```

脚本将 [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 安装到 `external/MediaCrawler`，固定提交：

```text
d6f7c5bb906b6dac40ddf343ef9e26438a3de092
```

采集器固定使用自己的 **Python 3.11** `.venv`，不与 FastAPI 环境混装。缺少 3.11 时，安装脚本会调用 Python Install Manager 的 `py install 3.11` 下载；没有该管理器时需先安装 Python 3.11 或 Python Install Manager。已有其他版本的环境会移到同目录 `.venv-incompatible-*` 备份，再创建 3.11 环境，登录配置仍保留在采集器目录。运行时也会检查提交版本，防止自动升级改变字段。升级时需要同步调整适配器和桥接程序，再由你验证。

### 在前端安装、启动和登录

点击页面右上角 **小红书采集器**，也可从“参考攻略”的提示或“当前接入状态”进入。

1. 未安装时点击 **安装采集器**；已有目录但安装失败时点击 **修复并重新安装**。后台仅安装独立采集环境和 Chromium，不重新安装旅行项目的前后端依赖。依赖和浏览器驱动准备完成后才写入 `.venv/travel-agent-ready.json` 完成标记；只有目录或 Python 可执行文件时显示“安装未完成”。诊断保存在 `backend/data/crawler-install.log`。
2. 首次使用且账号正常时点击 **打开登录窗口**。后台打开本机可见的小红书浏览器窗口，由你扫码；登录过程不搜索帖子，完成后仍保持停用。账号异常时先在官方客户端处理，不要反复扫码。
3. 已有登录状态时直接点击 **启动采集器**。启动时检查依赖能否加载以及 Chromium 文件是否存在，失败时显示原因，详情保存在 `backend/data/crawler-start.log`。启用设置即时生效，无需编辑 `.env` 或重启后端；之后按旅行攻略搜索请求采集。
4. **停止采集器** 会停用后续采集，并取消正在进行的采集、安装或登录进程。关闭面板不会取消任务，重新打开可查看进度。

启用状态保存到 `backend/data/crawler-config.json`，覆盖 `.env` 的 `CRAWLER_ENABLED` 默认值，重启后保留；安装未完成时保持停用。登录仍使用采集器自己的本机浏览器配置，不将 Cookie 发给前端，登录错误详情保存在 `backend/data/crawler-login.log`。采集路径可在 `.env` 配置；前端安装要求 `MEDIACRAWLER_PYTHON` 指向该采集目录的 `.venv/Scripts/python.exe`。自定义目录可用 `scripts/setup.ps1 -CrawlerOnly -CrawlerDirectory <目录>` 准备环境。

应用通过 `crawler_bridge.py` 在独立进程中调用固定版本，不修改上游源码。采集只能从前端手动搜索触发；规划只使用用户勾选的已保存攻略，不再按城市自动搜索或读取仅链接导入。每轮只搜索一个关键词，搜索接口返回一页后只读取最多三篇详情。规划时解析用户确认的攻略，由模型在指定天数内组合候选路线。搜索缓存默认二十四小时，包括零结果，资源报价不使用这个缓存。

桥接层限制 Python 采集接口请求：串行执行、每次响应结束后至少间隔六秒、每轮最多五次请求；取消上游一秒间隔自动重试和详情 HTML 回退。浏览器打开页面所需的资源请求不在这个接口计数内。采集与登录共用至少一分钟的轮次开始间隔，记录保存在 `crawler-config.json`，重启不会清除。禁用评论、媒体下载和代理池。

检测到 HTTP 401/403/429/461/471、账号限制响应或验证码信息时，立即停止后续采集接口请求，并持久化保护锁；安装、登录和重启均不会解除保护。请先在官方客户端处理账号异常，确认恢复后点击 **账号已恢复，解除保护**；解除后仍保持停用，不自动恢复采集。降低频率不能保证不触发账号限制；这些参数只是减少请求量，不是平台认可的安全阈值。已报告的账号异常已将本机采集设置为锁定。

带 `xsec_token` 的完整笔记链接更适合指定采集；分享短链能否被上游解析取决于固定版本支持情况。无法读取短链时请从原帖复制完整链接，或导入文字、图片。

MediaCrawler 使用[非商业学习许可证](https://github.com/NanmiCoder/MediaCrawler/blob/d6f7c5bb906b6dac40ddf343ef9e26438a3de092/LICENSE)。本项目没有复制其源码或更改其许可；第三方代码、登录态和生成数据在 `external/`、`backend/data/` 内，默认不加入 Git。代码许可不代表获得小红书或攻略作者的内容授权。

### 飞猪 CLI

项目通过 `model-runtime` 安装[官方 CLI](https://github.com/alibaba-flyai/flyai-skill)，运行 `scripts/setup.ps1` 会一并安装；无需另外全局安装。也可以使用已有的全局 CLI：

```powershell
npm install -g @fly-ai/flyai-cli
```

应用使用 `search-train`、`search-flight`、`search-hotel` 和 `search-poi`；默认启用，优先使用指定路径或 PATH 中的程序，默认 `flyai` 找不到时使用项目内安装的 CLI。Windows 下从 npm 包读取 `bin`，直接调用 Node 入口，并通过 `model-runtime/flyai-exit.cjs` 让 CLI 输出与网络句柄清理后自然退出，避免查询结束时触发 `UV_HANDLE_CLOSING` 断言；兼容文件只加载到飞猪子进程。不通过 shell 拼接用户输入。接入状态会检查 API Key 是否已配置、程序、Node 入口和兼容文件是否存在；实际接口权限及库存仍需查询确认。

在页面右上角 **飞猪配置** 中粘贴已申请的 API Key 并保存；“当前接入状态”中也有入口。保存后立即生效，无需重启后端，后续查询通过 `FLYAI_API_KEY` 传给官方 CLI。已保存 Key 不返回前端，也不存入浏览器；配置保存在本机 `backend/data/flyai-config.json`，优先于 `.env`。清除 Key 后停用飞猪查询，重启后也不会恢复环境变量或 CLI 内置默认凭证。旅行任务运行时暂不允许修改 Key。

```dotenv
FLYAI_ENABLED=true
FLYAI_COMMAND=flyai
FLYAI_API_KEY=
```

本项目要求配置自己的 API Key；未通过页面保存配置时，也可以填写上面的 `FLYAI_API_KEY` 环境变量。独立 CLI 的免密钥查询与本项目的配置策略不同。账号权限、库存、频率和字段仍需实际查询确认。已有行程不会因保存 Key 自动重查；在费用记录中点击“更新报价与路线”，按当前需求重查未锁定的交通与住宿、门票和地图路线，保留当前活动选择。旧任务在游玩阶段恢复时，会重查此前缺失且未锁定的必要交通；酒店未由用户采用时不影响路线继续规划。

适配器覆盖常见 camelCase/snake_case 字段。未知结构会记录到本机 SQLite 的 `queries` 表，并显示“返回字段尚未识别”；如你的实际返回采用其他字段，需要补充 `app/adapters.py::normalize_resources` 的映射。不会让模型从营销文字推测价格。

费用规则：

- `ticketPrice` / `ticket_price` 按每人每段计算；官方 `adultPrice + journeys[].segments[]` 响应将成人价与同一行程的到离时刻、车次/航班号和站点一起解析，只采用符合查询日期的单程结果。
- 单晚 `pricePerNight` / `price_per_night` 可按房间数计算；多晚报价不会假设每晚价格相同。
- 整段报价只有响应明确匹配人数，或房间数及入住离店日期时，才计入已知费用。
- 通用 `price` 为口径未知，`minPrice` 为起价，都不能计入确定的总费用。
- 官方酒店 `shId` 记录的展示 `price` 可按每间每晚乘房间数、晚数作参考估算，各晚实际价格仍待核对；与已知费用分开显示。
- 景点通过 `search-poi` 获取 `ticketInfo`。唯一匹配、日期相符的门票展示价计入参考估算；空价格不代表免费，日期不相符只展示参考。票种、适用人数和最终结算仍需核对。
- 高德返回的公交路线费用计入市内交通参考估算；开放时间、地点歧义和路线耗时缺口归入“行程信息待确认”，不计入未知费用数量。
- 没有明确价格口径、非人民币或缺少报价时保留未知项。餐饮暂按每人每天一百元估算。

### 高德 MCP

按[官方说明](https://developer.amap.com/api/mcp-server/create-project-and-key)在高德开放平台创建应用、添加服务平台为“Web 服务”的 Key，然后在页面右上角 **高德配置** 中填写并保存；“当前接入状态”旁也有“配置 Key”入口。保存后立即生效，无需重启。已保存 Key 不会返回前端，配置保存在本机 `backend/data/amap-config.json`，优先于环境变量；清除 Key 会停用高德查询，重启后仍保持未配置。旅行任务处理中暂不允许修改 Key。

没有网页保存配置时，仍可通过 `backend/.env` 配置；修改环境文件需要重启后端。没有 Key 时显示“未配置”是正常的：

```dotenv
AMAP_API_KEY=你的高德Key
```

也兼容官方 Node MCP 的变量名 `AMAP_MAPS_API_KEY`，只需填写其中一个；应用自行读取环境配置，不会自动使用其他客户端的 MCP 配置。

使用[官方 Streamable HTTP 地址](https://developer.amap.com/api/mcp-server/gettingstarted)，通过 MCP SDK 初始化、读取工具输入结构，调用地点搜索、详情、天气及路线工具。地点搜索只有 POI ID、没有经纬度时，再调用 `maps_search_detail` 取得坐标。多个结果会结合攻略依据或酒店地址匹配实际 POI；无法唯一匹配的分店/同名地点保留歧义，不直接取第一个结果生成导航。

地图未配置或查询失败时，移动时间标为待确认，市内路线暂预留四十五分钟；车站/机场接驳暂预留六十分钟，并明确为估算。景点开放时间和门票中的攻略描述保持“攻略提及，当前待确认”，不作为营业或价格保证。

## 4. 运行与数据流

四个专责 Agent 由 LangGraph 编排：攻略、资源、行程、检验。协调器继续使用 Planner 代码；交通、住宿与门票属于资源 Agent，路线、日程与餐饮属于行程 Agent。角色可以共用已配置模型，各有独立指令、上下文和结构化交接；去重、金额、时间、权限与版本检查由代码执行。

```text
需求与所选攻略 → 攻略整理 → 行程初案 → 交通住宿查证 → 每日行程与全程餐饮
                                                         ↓
                    完整候选 ← 独立重审与最多两轮返工 ← 门票状态与代码检查
                       ⇅ 局部修改后重审
                 用户确认并保存同一份行程
```

攻略正文证据必须匹配原文并包含地点名称；图片证据必须引用实际输入的图片序号，但图文模型的识别正确性仍需人工核对。候选路线严格覆盖起止日期并保持城市顺序，只能引用已解析的活动 ID。图片只读取可信小红书 CDN 或本地上传文件，不能由模型任意提供 URL。

缺信息、缺可用攻略、等待追问回答、确认需求或选择路线时使用 `interrupt()`，SQLite 保存检查点。追问每次只提出一题，用户提交这一题后，再依据最新回答决定下一问；提供推荐答案与可选项，也接受自由回答，推荐不会自动接受。起止日期、城市、人数、房间数和预算由需求表维护，追问只补充偏好、交通选择与房型。候选修改通过日期范围合并，其他日期保持原内容；修改结果仍检查日期、城市顺序与活动来源。

每次运行有独立 ID；同一旅行拒绝并发修改。网页关闭不取消后台任务，SSE 可按事件 ID 重新连接。服务停止或意外退出后任务变为可恢复状态，通过“继续本次任务”恢复检查点；非幂等外部查询可能重新执行，但不会重复写入已生成的草稿。

每日行程生成、修改或锁定后先保留为草稿，刷新后仍可查看，但不新增行程版本。点击 **保存行程** 才新增已保存版本；未修改的已保存行程不重复保存。可通过版本下拉框查看已保存快照，并在每日行程中删除该版本，或删除当前未保存草稿。删除当前行程后可以重新规划，旅行需求、参考攻略和其他已保存版本保留；旧版本号不复用，因此删除后编号可能不连续。保存、删除时检查当前版本号及更新时间，防止旧页面操作覆盖新的草稿。原有自动保存的历史版本继续保留。

行程修改使用当前行程（包括未保存草稿）作为基础；已删除的活动不会因下一次换酒店而从原始候选路线重新出现。酒店变化重算相应城市路线；局部修改中明确要求保留的城市不参与自动降价或删减。锁定安排保留核心内容和时间，移动路线可更新；锁定与新条件冲突时仍展示问题，由用户解除锁定或调整需求。历史快照同时保存攻略内容与解析依据，之后导入新攻略不会改写历史引用。

需求表的“市内出行”与高铁/飞机等跨城交通分开设置，默认步行＋公交/地铁。“不打车”会限制允许的路线；公交查询失败时不会改用打车，缺少地点或路线时显示待确认并预留估算时间。每天显示移动方式、地图预计耗时、步行距离及可取得的公交地铁线路，移动与末段返回住宿/前往车站机场的时间均占用日程。报价之外的市内交通费用仍待确认。

生成候选路线前查询攻略地点坐标与城市天气，模型按地理区域分配每天活动；正式细化时对同一天最多12处活动计算坐标距离较短的顺序，并比较原顺序与重排顺序的实际地图路线耗时（含起终点），减少绕路折返。这是有限候选比较，不保证全局最短路线；锁定活动或明确的时间顺序优先，必要折返与定位/路线缺口会说明。地图耗时是查询时的估计，并非未来出行日期的运行时刻保证。

天气只使用高德返回且日期完全匹配的预报，不把今天的天气用于远期行程。对应日期有雨雪等天气时，模型优先选用已有攻略的室内活动，并保留必去项、提示户外风险；无对应预报时显示“临近出行需再查询”。修改或重新生成时再次查询（天气缓存15分钟，路线缓存5分钟），未实现后台定时更新。

`backend/data/` 保存：

| 文件/目录 | 内容 |
|---|---|
| `trips.sqlite` | 会话、攻略、历史版本、执行事件、外部查询记录与搜索缓存 |
| `checkpoints.sqlite` | LangGraph 中断与恢复检查点 |
| `uploads/` | 标准化后的攻略图片 |
| `crawler/` | 各次采集的独立输出与请求参数 |

备份时先停止后端，再复制整个 `backend/data/`；同时保留两份 SQLite 和图片。当前不提供自动删除或数据迁移功能。

### 主要 API

| 接口 | 输入与作用 |
|---|---|
| `POST /api/trips` | JSON：`title`、可选 `requirements` |
| `GET /api/trips` / `GET /api/trips/{id}` | 列表、当前状态、来源和当前运行 |
| `POST /api/trips/{id}/sources` | multipart：`title`、`url`、`text`、`city_hint`、`files`、`base_version` |
| `POST /api/trips/{id}/messages` | JSON：`content`、`requirements`、`base_version`、`retry`、`selected_source_ids`；回答追问时传 `interview_response: {round_id, answers, note, confirm}`，返回 `run_id` |
| `POST /api/trips/{id}/selection` | JSON：`candidate_id`、`base_version`；返回 `run_id` |
| `POST /api/trips/{id}/candidates/revise` | JSON：`candidate_id`、`dates`、`content`、`base_version`；只修改指定日期，返回 `run_id` |
| `DELETE /api/trips/{id}?base_version=N` | 删除旅行及其攻略、会话、历史版本、运行/查询记录和检查点；运行中或版本过期时拒绝 |
| `PATCH /api/trips/{id}/locks` | JSON：`item_id`、`locked`、`base_version`；更新草稿，不新增版本 |
| `POST /api/trips/{id}/itinerary/save` | JSON：`base_version`、`updated_at`；手动保存当前草稿为新版本 |
| `DELETE /api/trips/{id}/itinerary?base_version=N&updated_at=T` | 删除当前草稿或当前已保存行程；可传 `version=V` 删除指定版本，保留旅行需求和攻略 |
| `GET /api/trips/{id}/versions` | 历史完整快照 |
| `GET /api/runs/{id}/events` | SSE，支持 `after` 和 `Last-Event-ID` |
| `GET /api/capabilities` | 配置是否存在，不返回密钥，也不探测外部接口 |

`retry=true` 在中断等待时继续或重新检索；失败检查点存在时重试失败节点；已完成行程则重新生成候选方案。过期 `base_version` 或已有运行返回 HTTP 409。

## 5. 你来验收

### 本次流程与查询改进

候选及每日行程为攻略明确涉及购票的活动查询门票，也为未写票价的博物馆、动物园、展馆及主题乐园等场馆查询参考。攻略明确免费开放的地点不默认查票，普通街区也不会凭空添加票费；各游览活动都可手动查询。查询结果、多个票种或缺价原因显示在对应景点下；没有报价不代表免费，未核实收费或票价仍列为预算待确认。飞猪名称可匹配当前活动的攻略别名；两个不同供应商地点不能自动选定。手动重查不受近期报价缓存拦截，价格仍需在预订页核对日期和适用票种。

住宿查询和备选集中在“酒店与门票”，每日行程不再重复显示整套酒店商品查询面板。在旅行需求里可为每座城市指定住宿区域，留空时按所选路线的活动位置推荐；酒店查询也可选择沿线推荐区域、手动指定路段或全市查询。确认行程后，可以点击“按这个区域重查行程住宿与接驳”，仅更新对应城市，锁定住宿须先解锁。

各步骤上方提供返回上一步和返回步骤选择。返回需求确认可修改偏好，返回候选选择会重新开放路线选择；旧行程保留为待更新内容，已保存版本不删除。右侧只显示当前实际规划步骤，移除历史事件列表和推断的阶段勾选。

修改源码后，请由你依次运行根目录的 `stop.bat`、`build.bat`、`start.bat`，再刷新 `http://127.0.0.1:8000`。`build.bat` 会先更新后端依赖（新增本地二维码组件），再打包前端。本次没有执行安装、测试、构建或真实接口查询，已有 `frontend/dist` 仍是此前的页面。

- 旅行需求使用独立保存接口，保存成功后进入参考攻略页；修改需求会使旧追问和候选失效，保留攻略、旧行程及已保存版本。
- 攻略必须由用户主动勾选。提交攻略后进入追问，最终确认需求后进入候选，确认路线后进入每日行程；每一步显示加载动画。后台终态和 SSE 结束事件共用状态同步，窗口聚焦和断线恢复也会同步任务状态，查看历史版本时暂停自动跳页。
- 侧边栏和页面新增“酒店与门票”入口，不需要先生成行程或配置模型。酒店可指定入住和退房日期；景点接口只提供资料和参考价，没有指定游览日库存查询能力。具体门票票种与价格请在飞猪详情页核对。没有价格不会显示为免费，也不会让模型补出价格。
- 飞猪错误按组件、鉴权、网络、限流、参数和格式分类，脱敏诊断、退出码、查询时间保存在 SQLite `queries` 表；未配置和暂停的查询也有记录。失败、无候选和字段未识别分别展示。酒店、交通、景点提供单项重新查询入口。
- 追问界面每次只显示一题，提交后立即记录回答，再动态生成下一问；需求摘要和推荐理由可展开查看，推荐答案不自动接受。旧批量追问记录也只激活第一题，后续问题依据新回答重新决定。

### 网页地图与手机高德

“每日行程”的网页地图按日期展示已定位点、编号和顺序虚线。虚线是地点顺序示意，实际道路或公交路线请使用每段导航。未定位点明确列出；底图加载失败可重试。

网页地图需要另建服务平台为 **Web端(JSAPI)** 的 Key 及其配套安全密钥，在“高德配置 → 电脑网页地图”保存；与原来的 **Web 服务** Key 分开。域名白名单应允许你实际访问的本机地址。浏览器仅取得 JSAPI Key，安全密钥由本机 `/_AMapService` 代理注入，保存在 `backend/data/amap-web-config.json`，不回显。更换已加载的 JSAPI Key 后需要刷新页面。参考[高德 JSAPI 安全配置](https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode)。

“导出到手机高德”保留官方返回地址并提供复制与本地生成的二维码。`amapuri://` 是高德 App 唤起地址，不能作为电脑网页打开；手机扫描器与高德客户端是否支持唤起仍需实际确认。只在服务真实返回网页地址时提供该地址。二维码编码的是高德地址，不是本机 `127.0.0.1` 页面；历史版本也可以查看已保存的导出入口。超过单日16个导出点和未定位点都会列出提示。

新增接口：`PATCH /api/trips/{id}/requirements`（需求、`base_version`、`updated_at`）；`GET/PUT/DELETE /api/system/amap/web`；`GET /api/maps/web-config`；`GET /api/trips/{id}/maps/qrcode`。独立查询仅保留 `hotel`、`poi` 模式及日期筛选；更新报价可以传 `resource_ids`，景点标识为 `ticket:<activity_id>`。

新版前端的规划提交、追问回答、候选选择、局部修改和报价更新都会传 `updated_at`；后台在创建运行前检查它，拒绝过期页面提交。旧 API 客户端省略此字段仍保留兼容行为。

见 [验收清单](ACCEPTANCE.md)。第一版支持 1–30 天、最多八个不重复目的地、1–20 人、1–10 间房；参数限制只是控制个人原型任务量，不是资源服务的库存保证。

## 协作规划与路线确认

当前主线是：选择攻略 → 攻略 Agent 整理景点与来源 → 行程初案 → 资源 Agent 查交通住宿 → 行程 Agent 安排实际日期、顺序、时段和全程餐饮 → 资源 Agent 补门票状态 → 代码检查 → 检验 Agent 完整重审 → 一条通过审查的候选或待处理草稿 → 局部修改后重审 → 确认并保存同一份每日行程。

- 四个 Agent 使用当前已配置模型，各有独立任务、上下文和结构化交接。行程 Agent 可请求地点、允许交通方式的路线、天气和攻略替代建议，资源 Agent 只选择已查询的资源；检验 Agent 只读完整快照与来源/查询依据。工具参数受城市与所选攻略 ID 约束，协调器统一执行与合并。
- 景点按统一实际地点身份合并来源，保留各篇攻略的引用；全程默认不重复游览同一地点。同城道路与步行街简称（如北京路／北京路步行街）即使 POI ID 不同，也结合名称、地点类型及 500 米内的位置识别重复；尚未定位时只合并名称身份，不补造地图依据。旧草稿重审与确认同样重新计算身份，旧版审查报告需更新。餐饮按门店在午晚餐与不同日期之间统一分配，先给各餐次推荐，再补备选；来源不足时减少推荐。同品牌不同分店和同一建筑内不同地点不能仅凭坐标合并。
- 生成候选时先按实际地点合并模型可选项，并交接全部攻略引用。模型仍返回普通重复项时，代码先保留一次游览并写明合并原因，再严格校验；锁定项、采用的体验商品和日期限定的再访授权不会被静默删除。合并后缺少活动的日期继续保留并说明资料缺口，不虚构补点；确认和保存仍校验已展示的原方案，不在提交时偷偷修改行程。
- 完整候选必须重审地点、餐饮、来源、用户约束、时间、用户已采用住宿、费用、事实、整体合理性与修改范围。未选酒店时住宿审查不适用，不要求补选酒店。发现返工交给责任角色，最多两轮；失败或关键事实缺失不能自动当作通过。非阻断的天气或价格缺口仍明确展示，不保证总预算、库存或未来营业。
- 攻略建议分组以现有地点的实际城市为准，自动校正城市标签、拆开跨城组、去掉餐饮和重复 ID。未知 ID 会要求模型纠正一次；仍错误时只回退为所选资料的城市基础分组，不采用虚构地点。必去、排除及待回答问题继续保留，约束错误仍阻断。建议分组的回退不代表完整候选已通过检验。
- 市内出行选“步行＋公交 / 地铁”时，超过 1.5 公里的直线距离、步行路程超过 1.5 公里或步行耗时超过 25 分钟的路段优先公交/地铁；公共交通缺失时保留待补齐状态，长步行只作备选参考。“只步行”仍遵守用户选择。
- “补齐依据并重新审查”保留已有景点、时段、餐饮和成功交通依据，只补缺失路段及旧的长步行方案；不清空成功缓存，不整趟重查交通、酒店与门票。地图路线成功缓存复用 30 分钟，始终保留原查询时间。
- 每轮修改前保留上一轮快照。地图查询超限、至少两个且占原已知路段一半的依据失效，或新增至少三项阻断冲突时，自动恢复上轮计划并重新审查。任务异常时也恢复上轮候选展示；当前需求和攻略选择不会静默改回，旧报告不能直接冒充新审查。高德频率限制先降低频率并等待重试，日配额耗尽或重试仍失败时才暂停后续请求；旧路线继续保留。
- 高德调用按服务实例共享最多 3 个并发，同一轮规划和不同旅行任务均受此限制；正常情况没有固定请求间隔。仅收到 QPS/频率错误后，增加 0.5–2 秒的请求间隔并等待退避，最多重试两次；冷却等待不占用并发名额。分钟窗口限制等待至少 65 秒，HTTP 429 遵守数值 Retry-After。并发数与每秒请求数分别控制。日配额错误单独标为 `amap_quota_limit`，不靠反复重试消耗请求；仍无法恢复时保留旧路线。查询记录保存安全的高德错误码、真实尝试次数与本地拦截标记，不保存错误响应里的凭据。
- 审查绑定完整计划、需求、来源、锁定项、回答历史与查询依据；局部修改、资源切换、报价刷新和返回旧候选都经过同一门禁。审查与资源报价最多保留十分钟有效期，过期须更新依据；旧候选没有审查报告时不能确认，旧已保存历史仍可查看。
- 前端新增独立审查结论、发现和“补齐依据并重新审查”入口；后端在选择、确认、保存及幂等恢复路径同样校验，不能通过旧报告绕过阻断。测试用例新增于 `backend/tests/test_four_agent_review.py`，由用户运行。
- 景点保留正文/图片证据和原攻略日序，实际旅行日期由路线 Agent 决定。明确必去的景点不会被自动删除；普通可选景点可调整并说明原因。旅行需求中可清除必去/排除标记。
- 规划中需要用户决定时出现一道问题。回答后恢复相关步骤；“需求追问”页保留回答历史，可重新回答已有问题。没有必要决策时直接继续，不强制确认一段空问题总结。
- 候选包含景点时段、逐段交通、天气与住宿区域。门票价格在候选阶段由飞猪按景点和日期查询；缺价不是免费。未来天气只用高德实际覆盖的日期，没有预报则标明待复核。
- 景点位置或关键交通耗时未核实时不能确认，可点击“保留路线，补齐地图依据”。游玩时长可能是攻略参考或路线 Agent 的明确估算；交通耗时为查询时参考，不声称验证了未来某班公交。
- 确认请求核对草稿版本、完整内容摘要及需求/攻略指纹，直接保存已展示的路线，不再次生成或排序。每日行程与候选使用同一展示组件。
- 指定日期修改只重算相关日期；住宿/跨城交通变化重算实际依赖的接驳。已确认版本保留，修改草稿重新确认后才替换。报价/天气刷新若不改路线结构，仅更新事实；产生结构变化时展示新候选。
- 普通返回只切换页面，不清空问题或重启任务。“打开路线修改草稿”与“重新回答这一题”才会开始相应修改。
- 每轮协作最多四次模型推进，工具请求最多三轮、每轮四项，继续沿用高德单批查询上限。超限保留依据并报告未完成，不伪装成可确认路线；必要的用户问题没有固定四轮访谈限制。
- 已完成的 Agent 交接与成功工具观察保存在本机 SQLite 的 agent_results/queries。恢复任务校验运行 ID，拒绝旧任务迟到结果。规划过程中不自动搜索或勾选新攻略。

旧候选缺少完整草稿时，请重新协作规划；旧保存版本保留可查看。源码修改不等于前端已经打包。本次改造未运行构建、测试或实际服务查询；由用户自行停止服务、运行 build.bat、再运行 start.bat，并按 docs/TRAVEL_PLANNING_IMPROVEMENT_PLAN.md 的场景验收。
